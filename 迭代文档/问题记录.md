# 项目问题记录

从项目创建至今遇到的所有问题、根因及解决方案。

---

## 一、字幕提取

### 1. 两个平台都报「该视频没有可用字幕」

**现象**：粘贴 YouTube 和 Bilibili URL 都提示无字幕。

**根因**：YouTube 的 `except Exception: return []` 静默吞掉所有错误；Bilibili 大部分视频没有 CC 字幕（只有硬字幕）。

**解决**：
- YouTube：改为 3 级回退（youtube-transcript-api → yt-dlp下载SRT → Whisper语音识别），抛出具体错误信息
- Bilibili：双端点尝试 + 明确错误提示，回退 Whisper

**改动文件**：`src/extractors/youtube.py`, `src/extractors/bilibili.py`, `src/transcriber.py`, `src/web/server.py`

---

### 2. youtube-transcript-api v1.x API 变更

**现象**：`YouTubeTranscriptApi.get_transcript()` 报 `no attribute 'get_transcript'`。

**根因**：库从 0.x 升级到 1.x，API 改为实例化后 `list()` + `fetch()`。

**解决**：创建 `api = YouTubeTranscriptApi()` 实例，`api.list(video_id)` 列出语言，`api.fetch(video_id, languages=[...])` 获取。

**改动文件**：`src/extractors/youtube.py`

---

### 3. YouTube 自动生成字幕获取不到

**现象**：某些视频 `api.list()` 返回空或只有少量语言。

**根因**：部分视频上传者禁用了字幕功能（`TranscriptsDisabled`）。

**解决**：列为预期错误，触发 yt-dlp 回退或最终 Whisper 回退。

---

## 二、语音识别 (Whisper)

### 4. ffmpeg 未安装导致音频下载失败

**现象**：`yt_dlp.utils.PostProcessingError: ffprobe and ffmpeg not found`

**根因**：下载配置中指定了 `FFmpegExtractAudio` 后处理器，但 Windows 未装 ffmpeg。

**解决**：去掉后处理器，直接下载原生音频格式（m4a/webm），faster-whisper 用内置 av 库解码。格式优先级：`bestaudio[ext=m4a]/bestaudio[ext=webm]/bestaudio/best`。

**改动文件**：`src/transcriber.py`

---

### 5. Path.rmdir() missing_ok 报错

**现象**：`TypeError: Path.rmdir() got an unexpected keyword argument 'missing_ok'`

**根因**：Python 版本兼容性问题。

**解决**：用 `try/except OSError` 替代 `missing_ok=True`。

**改动文件**：`src/transcriber.py`

---

### 6. CPU 语音识别太慢

**现象**：medium 模型 26 分钟视频转录需 ~25 分钟。

**根因**：模型太大，纯 CPU int8 推理。

**解决**：逐步优化：
1. 模型 medium → small → tiny（精度换速度）
2. `beam_size=5 → 1`（贪心解码）
3. `vad_filter=True`（跳过静音段）
4. 最终：GPU 自动检测 `small + cuda + float16`，CPU 回退 `tiny + int8`

**改动文件**：`src/transcriber.py`

---

### 7. GPU 检测到但无法使用 (cublas64_12.dll)

**现象**：`RuntimeError: Library cublas64_12.dll is not found or cannot be loaded`

**根因**：CUDA Toolkit 13.3 系统中的 cuBLAS DLL 版本不匹配，CTranslate2 需要 CUDA 12 的 `cublas64_12.dll`。`nvidia-cublas-cu12` pip 包已安装该 DLL 到 site-packages，但 Python 的 `os.add_dll_directory()` 对 C 扩展模块无效。

**解决**：在模块顶层（`import faster_whisper` 之前）用 `os.environ["PATH"]` 注入 nvidia 各包的 bin 目录。同时检测系统 CUDA Toolkit 路径。

**改动文件**：`src/transcriber.py` — `_inject_cuda_path()` 函数

---

### 8. int8_float16 在 CPU 上不支持

**现象**：`ValueError: Requested int8_float16 compute type, but the target device or backend do not support efficient int8_float16 computation`

**根因**：混合精度仅特定 CPU 支持。

**解决**：`_get_model()` 中按 `("int8_float16", "int8")` 顺序尝试，失败自动降级。

**改动文件**：`src/transcriber.py`

---

### 9. temperature=0.0 导致转录循环重复

**现象**：英文视频被识别成"好,所以我們現在在這裡..."循环 14 次。

**根因**：`temperature=0.0` + `beam_size=1` 使 softmax 分布过于尖锐，Decoder 陷入循环。

**解决**：去掉 `temperature=0.0`，保留 `num_workers=2` 和 `word_timestamps=False` 两个安全优化。

**改动文件**：`src/transcriber.py`

---

## 三、LLM 调用

### 10. DeepSeek 返回 ThinkingBlock 报错

**现象**：`AttributeError: 'ThinkingBlock' object has no attribute 'text'`

**根因**：DeepSeek 的 Anthropic 兼容端点返回 type="thinking" 的 content block，不是 text block。

**解决**：遍历 `r.content`，跳过非 text 类型，只取 `type == "text"` 的块。

**改动文件**：`src/llm.py`

---

### 11. 12 小时长视频解析失败

**现象**：长视频无响应或超时。

**根因**：Map-Reduce 固定只切 4 块，每块超大；块摘要 token 只有 1024；无进度反馈；SSE 超时 300s。

**解决**：
- 动态分块：~15K 字/块，最多 12 块
- >6 块时双层 Map-Reduce
- 块摘要提升至 2048 token
- SSE 超时延长至 900s
- 新增进度回调推送分段进度

**改动文件**：`src/analyzers/summarizer.py`, `src/web/server.py`

---

## 四、格式化与编码

### 12. Unknown format code 'd' for object of type 'float'

**现象**：`f"{4.0:02d}"` 崩溃。

**根因**：yt-dlp 返回的 `duration` 是 float，`divmod(float, 60)` 返回 `(15.0, 4.0)` 浮点数，`:02d` 要求 int。

**解决**：所有 `divmod(x, 60)` 前加 `int()`；extractor 中 `duration=int(info.get("duration", 0) or 0)`。

**改动文件**：`src/output/markdown.py`, `src/extractors/youtube.py`, `src/extractors/bilibili.py`, `src/web/server.py`

---

### 13. ChromaDB 集合名非法字符

**现象**：`Validation error: name: Expected a name containing 3-512 characters from [a-zA-Z0-9._-], starting and ending with a character in [a-zA-Z0-9]`

**根因**：URL 片段含 `?`、`=` 等字符，`_sanitize_task_id` 未确保首尾为字母数字。

**解决**：`strip("_.-")` 去除首尾非法字符 → 首字符非字母则补 `v_` → 过短则 MD5 hash。

**改动文件**：`src/web/server.py`

---

### 14. Emoji 文件名导致迁移脚本遗漏

**现象**：`🚀国产MiniMax...` 文件夹中 `keypoints.md` 已归类，但 `overview.md` 和 `subtitles.md` 留在 output/ 根目录。

**根因**：旧迁移脚本的正则匹配失败（emoji 前缀）。

**解决**：手动 `mv` 剩余文件，后续新解析直接使用子文件夹结构。

## 五、UI

### 15. 进度文本逐行追加导致页面过长

**现象**：Whisper 转录阶段每秒一条进度推送，26 分钟视频堆积 350+ 行文本。

**根因**：前端 `prog.innerHTML += ...` 逐行追加。

**解决**：SSE 事件类型化（`status`/`download`/`transcribe`），前端改为固定 3 行布局（状态文本 + 下载进度条 + 转录进度条）。

**改动文件**：`src/web/server.py`, `src/web/static/index.html`

---

### 16. 无主题切换

**现象**：只有深色模式。

**解决**：CSS 自定义属性 + `[data-theme="light"]` 覆盖 + `localStorage` 持久化 + 右上角 🌙/☀️ 切换按钮。

**改动文件**：`src/web/static/index.html`

---

### 17. 历史记录不显示封面

**现象**：实时解析有封面缩略图，点击历史记录没有。

**根因**：封面 URL 仅通过 SSE 推送（内存），`.md` 文件不存储。历史记录回读 `.md` 文件拿不到封面。

**解决**：分析完成后额外写 `meta.json`（含 title/platform/author/duration/url/thumbnail），历史详情 API 读取该文件。

**改动文件**：`src/web/server.py`, `src/web/static/index.html`

---

### 18. 历史记录排序不对

**现象**：侧栏按文件夹名字母倒序，不是按时间。

**根因**：`sorted(iterdir(), reverse=True)` 按名字排序。

**解决**：按 `overview.md` 的 `st_mtime` 倒序排序。

**改动文件**：`src/web/server.py`

---

### 19. 侧栏收起时按钮位置太近

**现象**：收起后开关按钮紧贴页面标题。

**解决**：`#sidebar.collapsed + #sidebarToggle { left: 0; top: 60px; }`

**改动文件**：`src/web/static/index.html`

## 七、运维

### 23. python -m src.web.server 后台启动退出码 127

**现象**：通过后台进程管理器启动后进程立刻退出。

**根因**：`reload=True` + `WatchFiles` 在 Windows 上 fork 子进程，父进程退出后子进程脱离。

**解决**：用户直接在终端运行 `python -c "import uvicorn; uvicorn.run('src.web.server:app', host='127.0.0.1', port=8787)"` 作为主要启动方式，避免 `-m` 的 reload 副作用。README 同步更新。

**改动文件**：`README.md`

---

### 24. 服务启动报 [WinError 10048] 端口占用

**现象**：`ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8787): 通常每个套接字地址只允许使用一次`

**根因**：上次启动的 Python 进程未退出，还占用 8787 端口。

**解决**：启动前先 `taskkill //F //IM python.exe` 清理残留进程。

**改动文件**：无（README 已更新启动命令含 taskkill 步骤）

---

### 25. Bilibili 412 Precondition Failed（三轮定位）

**现象**：解析 Bilibili 视频报 `ERROR: [BiliBili] ...: Unable to download webpage: HTTP Error 412: Precondition Failed`

**第一轮 — UA/Cookie/WBI 签名**（未解决）

以为 Bilibili API 全面要求 cookie → 添加 4 个 UA 轮换、412 指数退避重试、WBI 签名、cookie 文件加载、yt-dlp 也传 cookie。

实际测试发现：`httpx` 打 `api.bilibili.com` 的 REST API **一直返回 200**，并非 412 来源。

**改动文件**：`src/extractors/bilibili.py`, `src/config.py`, `src/web/server.py`, `src/transcriber.py`

**第二轮 — extract() 抛异常丢掉元数据**（解决部分问题）

发现视频无 CC 字幕时 `_fetch_subtitles()` 抛 `RuntimeError`，导致 `extract()` 终止并把已拿到的元数据（title/author/duration）全扔了。server.py 的 `except` 降级到 yt-dlp 做元数据提取，yt-dlp 抓 HTML 页面被 412 拦截。

修复：`extract()` 内 `try/except RuntimeError` 捕获字幕失败，返回空字幕但保留完整元数据。server.py 的 yt-dlp 降级路径也加 try/except 兜底。

**改动文件**：`src/extractors/bilibili.py`, `src/web/server.py`

**第三轮 — transcript.py 的 yt-dlp 音频下载**（真正根因）

前两轮后 412 仍出现。逐环节测试确认：

| 步骤 | 端点 | 方式 | 结果 |
|------|------|------|:--:|
| 视频元数据 | `x/web-interface/view` | httpx | 200 OK |
| 字幕信息 | `x/player/v2` | httpx | 200 OK（但无CC字幕）|
| **音频下载** | **`www.bilibili.com/video/...`** | **yt-dlp** | **412** |
| 流媒体 URL | `x/player/playurl` | httpx | 200 OK → DASH 音频流 |

真正根因：yt-dlp 试图抓取 `www.bilibili.com` HTML 页面获取视频信息时被 412，而 Bilibili 的所有 REST API（`api.bilibili.com`）通过 httpx + 浏览器 UA 可以正常访问，且 `playurl` API 直接返回 DASH 音频流 URL。

修复：`transcriber.py` 中 `download_audio()` 检测 Bilibili URL → 调用 `fetch_bilibili_audio_url()` 通过 `playurl` API 获取 DASH 音频直链 → httpx 流式下载（带进度），完全绕过 yt-dlp。

**改动文件**：`src/extractors/bilibili.py`（新增 `_BILI_API_PLAYURL`、`fetch_bilibili_audio_url()`）, `src/transcriber.py`（新增 `_download_bilibili_audio()`）
